# 个人网站开发文档

总仓库 blog 保存设计稿、接口契约和表结构说明。三个子仓库独立发布。阅读本文时，可结合本目录的《个人网站接口文档》和《数据库表结构》核对接口字段及迁移语句。

## 用户端

用户端由 blog-web 提供。访客可以浏览项目、阅读已发布文章、查看个人资料并申请友链。页面通过公开接口访问数据库；站点设置决定主题、页足及友链申请入口。

### 页面与数据

- 首页 / 分为个人介绍、精选项目和技术栈三屏。介绍使用站点与资料接口，精选项目请求 /api/projects?featured=1，技术栈请求 /api/skills?home=1。调整首页推荐内容时应核对筛选条件。
- 项目 /projects 读取公开项目列表，以响应式卡片展示名称与简介。关于页 /about 读取个人资料和工作经历，以时间线展示经历。
- 文章列表 /blog 的接口支持关键词、分类、标签和分页，仅查询已发布文章，先按置顶、再按发布时间排序。详情页 /blog/:slug 按 slug 加载正文，用 markdown-it 渲染并生成标题目录，正文中的原始 HTML 已禁用。

### 友链与异常状态

访客可在页足查看已通过的友链。开启申请后，网站名称、网址和联系邮箱为必填项，头像、简介和回链地址可选。通过人机验证并提交后，申请进入待审核状态。验收时分别验证申请关闭、验证失败、重复地址和提交成功，再核对公开列表。

文章详情需要覆盖有效及不存在的 slug。数据库缺失或版本过低时，访问首页应看到维护页；连接恢复后应重新检查首页和文章详情。

## 管理端

blog-admin 当前只有基础仓库文件。以下页面和操作是管理端设计稿定义的开发范围，尚待实现。管理界面统一使用 /admin 路径。

### 页面与工作流

- 登录与概览。/admin/login 规划密码、手机或邮箱验证码、扫码和第三方登录。可用方式取决于站点配置及账号绑定。登录后由 /admin 展示统计、访问趋势和待处理事项；扫码应用仍待选定。
- 内容发布。/admin/posts 支持搜索、状态筛选和分页。编辑器区分草稿、预览和发布，离开未保存文章时提示。/admin/taxonomy 管理分类与标签。联调时从保存草稿开始，发布后再从公开列表进入正文。
- 项目与资料。/admin/projects 维护排序和首页精选，/admin/profile 维护基本资料、技能、经历及联系方式。保存后分别在首页、项目页和关于页核对。
- 友链与文件。/admin/links 处理待审核申请、通过或拒绝并管理申请入口。/admin/files 提供上传、选择、复制地址和查询引用，供编辑器和站点外观设置共用。
- 配置。/admin/settings 管理外观、页足、登录方式、账号安全、开发者密钥与 AI 服务。/admin/system 规划数据库连接测试、初始化、升级、备份恢复和文件存储库。

### 账号与扩展能力

原设计采用单管理员账号，保留密码登录。访问令牌用于鉴权，刷新令牌通过 HttpOnly Cookie 保存。开发者密钥按内容读写和上传范围授权，数据库保存哈希及末四位。AI 编辑辅助及访客问答属于后续功能，模型凭据由后端保管。

## 前端

### 用户端工程

- 路由与布局。blog-web/app/pages 生成页面路由，app/layouts 中的 home.vue 和 default.vue 组织首页及内页。SiteHeader、SiteFooter、BgLayer、FullPage 和 FriendLinkDialog 位于 app/components。
- 请求与类型。首屏查询使用 app/composables/useApi.ts 中的 useApi，通过 useFetch 提取业务响应的 data；表单提交使用 apiRequest 获取完整响应并处理业务码。修改返回值时同步检查 shared/types/api.ts、页面调用方和接口契约。
- 样式与语言。当前使用 Vue 3、TypeScript、Naive UI、SCSS 和 Nuxt i18n。全局样式在 app/assets/styles，主题逻辑见 useSiteTheme 和 ThemeCssVars。中文路由使用原路径，英文界面使用 /en 前缀；改动文案时同步检查两套语言资源。
- 服务端渲染。页面元信息跟随站点及页面数据生成。浏览器事件在客户端生命周期注册。修改主题、布局或文章渲染时，检查首次访问、页面切换和窄屏显示。

### 管理端前端设计

管理界面规划使用 Vue 3、Vite、Element Plus、Vue Router 和 Pinia。常规页面共用侧栏与顶栏，登录和全屏编辑器单独布局。设置页将活动标签写入 URL 查询参数，使刷新后可回到原标签。编辑器、文件选择器和仪表盘图表由管理端工程维护。

### 同域部署与 NGINX 分流

- 精确匹配 /admin 并重定向到 /admin/。/admin/ 下的页面和静态资源由 blog-admin 提供。管理端构建设置 Vite base 为 /admin/，Vue Router 使用 createWebHistory(import.meta.env.BASE_URL)。管理端手写的静态资源链接也应使用该基路径。
- 管理端静态资源按实际文件返回，缺失的 /admin/assets/ 文件返回 404。管理页面的深链接回退到 /admin/index.html，确保刷新 /admin/posts 后仍可进入文章管理。
- 精确匹配 /api/admin，并按前缀匹配 /api/admin/，统一转发到 blog-server，保留完整请求 URI。认证接口位于 /api/admin/auth/，包括登录、令牌刷新、退出及第三方登录回调。
- 其余请求全部交给 blog-web，包括访客页面、公开接口 /api/site 和 /api/posts 等、Nuxt 资源 /_nuxt/ 以及 public 目录对外提供的文件。

### 本地开发与构建

从 blog-web 运行 npm ci、npm run dev 即可启动开发服务。生产构建使用 npm run build，入口为 node .output/server/index.mjs。也可在该目录运行 docker build -t blog-web:local . 构建 Node.js 24 镜像。容器工作目录为 /app，监听 3000 端口。

## 后端

### 已实现的公开接口

请求由 blog-web/server/api 处理，经 server/repositories 和 Kysely 访问 SQLite 或 MySQL。server/mock 中保留样例数据。排查页面内容时先核对实际连接、仓储筛选条件和接口响应。

站点与资料使用 GET /api/site、/api/profile、/api/skills 和 /api/experiences；项目使用 /api/projects。文章使用 /api/posts、/api/posts/:slug、/api/categories 和 /api/tags。友链读取使用 GET /api/friend-links，申请使用 POST /api/friend-links/apply。

友链申请处理器检查开放开关、Turnstile 配置、字段和验证票据，再写入待审核记录。重复网址返回冲突，同一来源每小时最多申请三次。服务端密钥通过 NUXT_TURNSTILE_SECRET 提供。

### 数据库生命周期与部署

- 新库。在 blog-server/database 中选择 schema.sqlite.sql 或 schema.mysql.sql，执行建表及 seed.sql。成功后按 version.json 登记 component_version 的模块 0。当前目标值为 1000001；只运行建表和种子脚本会留下版本 0。完整登记语句见《数据库表结构》。
- 升级。根据旧库版本选择 database/migrations 中对应数据库的脚本，成功后登记目标版本。blog-web/database/version.json 记录用户端要求的数据库版本，blog-web/server/assets/version.json 记录应用版本。
- 运行配置。用户端从进程工作目录读取 data/data.config，支持用 NUXT_DB_CONFIG_PATH 指定配置路径。默认 SQLite 文件为 data/blog.db。启动插件监听配置变更，定期检查连接和版本。自定义启动横幅可放在工作目录的 banner.txt，或由 NUXT_BANNER_PATH 指定。
- 测试部署。可将测试服务器的 /projects/blog/web/data 挂载到 /app/data。SQLite 数据库须已初始化，容器用户需要目录写权限以创建 WAL 文件。启动后访问首页及 /api/site 验证页面和数据库连接。

### 管理服务待实现范围

blog-server 当前维护建表、种子和迁移 SQL，管理服务的语言和框架仍待定。开发顺序可先打通管理员登录、发布文章、公开页面读取，再接入友链审核与站点设置。后续的存储库、数据库备份、开发者密钥和 AI 服务按管理需求接入。改表时同步更新两套建表脚本、迁移脚本和表结构文档。
